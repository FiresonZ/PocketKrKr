# 文字基线契约

## 目的

定义位图字体和运行时字体在测量、绘制、裁剪及缩放过程中的统一数据关系。本文只记录抽象契约，不绑定具体游戏、字体文件或平台实现。

## 统一字形数据

每个字符在进入绘制阶段后都应转换为同一种内部记录：

```text
bitmap:
  width, height
origin:
  x, y
advance:
  x, y
```

实际字形矩形由同一条记录计算：

```text
glyph.left   = draw.x + origin.x
glyph.top    = draw.y + origin.y
glyph.right  = glyph.left + bitmap.width
glyph.bottom = glyph.top + bitmap.height
```

## 数据来源

- 位图字体：使用文件中的字形尺寸、原点和推进量。
- 运行时字体：使用光栅化器生成的字形尺寸、bearing 和推进量。
- 缺字回退：只替换字形数据来源，不改变调用方的坐标契约。
- 测量、顶部/底部边界判断和最终绘制必须复用同一条内部字形数据路径。

## 基线要求

- 字形原点必须相对于同一个绘制基准定义。
- 不得把回退字体的 ascent 叠加到已经包含源字体基线的位图字形上。
- 旋转、阴影和描边只能通过明确的偏移或扩展矩形加入。
- 二次缩放必须以完整源矩形和目标矩形计算，不能把基线坐标误当成目标矩形左上角。
- 当字形比裁剪区域更高时，应保持确定性的对齐策略，并避免产生反向或零尺寸矩形。

## 验收

- TPF 命中、缺字回退和普通运行时字体的测量宽度与实际推进一致。
- `getTextWidth`、glyph draw rect、clip 判断和最终绘制对同一字符给出一致的几何结果。
- 全角字符、混排、阴影、旋转、负坐标和小尺寸裁剪均可重复验证。
- 不依赖游戏名、图层名、资源包名或固定字号特判。
