# 性能与重构

详细的待实施方案统一见 [optimization-roadmap.md](optimization-roadmap.md)。本文保留评估原则，避免与待办和架构文档重复。

## 优先级

| 优先级 | 方向 | 主要收益 | 风险 |
|---|---|---|---|
| 高 | 渲染目标与 GPU 资源生命周期 | 减少黑屏、旧纹理和上下文重建问题 | 高 |
| 高 | 视频帧提交与目标 Layer 合成 | 完成视频显示链路 | 高 |
| 中 | Flutter FFI 缓冲复用 | 降低回读路径分配和复制 | 中 |
| 中 | 字体缓存与预渲染度量 | 改善文本布局和字体切换稳定性 | 中 |
| 中 | TJS2 热路径 | 降低脚本密集场景 CPU 占用 | 高 |
| 低 | SIMD PS 混合恢复 | 提升特定混合模式吞吐 | 高，必须逐像素验证 |
| 低 | 头文件依赖收敛 | 缩短增量编译时间 | 中 |

## 评估规则

- 先测量，再优化；没有基准数据不改变热点代码。
- 任何像素、脚本、音视频、存档或生命周期优化都必须保留旧路径作为回归基准。
- 先做局部、可回退的改动，再考虑跨模块重构。
- 渲染和异步代码必须覆盖创建、重启、后台恢复、尺寸变化、异常和销毁路径。
- 以目标平台的帧耗时、峰值内存、功耗和兼容性结果作为最终判断，不以单一宿主机结果替代。
