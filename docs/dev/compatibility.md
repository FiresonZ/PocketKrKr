# 兼容性测试

## 测试闭环

```text
准备资源 → 运行 → 记录现象 → 分类定位 → 修复 → 回归
```

测试记录至少包含平台、系统版本、构建类型、资源类型、复现步骤、实际结果和期望结果。日志只保留与问题相关的片段，不提交个人路径或完整资源。

## 分类与入口

| 现象 | 排查位置 |
|---|---|
| 脚本报错或行为不同 | `cpp/core/tjs2/`、`cpp/core/base/` |
| 归档或资源读取失败 | `cpp/core/base/` |
| 花屏、色偏或图片缺失 | `cpp/core/visual/`、`cpp/plugins/psbfile/` |
| 动画缺帧或变形错误 | `cpp/plugins/motionplayer/` |
| 字体缺字或错位 | `cpp/core/visual/` |
| 音频或视频异常 | `cpp/core/sound/`、`cpp/core/movie/` |
| 插件接口缺失 | `cpp/plugins/`、ncbind 注册表 |
| 黑屏或停帧 | [渲染诊断](rendering-diagnosis.md) |

## 回归要求

- 修复脚本、存档、资源格式和生命周期问题时，检查创建、重启、异常和销毁路径。
- 修改像素混合时，同时运行标量与 SIMD 对比。
- 修改纹理或图层时，检查不同分辨率、透明度、裁剪和缩放。
- 修改字体时，检查预渲染字形、运行时字形、全角字符和混排文本。
- 结果以代码状态和可复现验证为准，不能仅根据单张截图判断兼容性。

## 外部行为对照

需要进行行为对照时，使用 [兼容性与参考资料](krkrz-compat.md) 中的统一入口。外部运行结果只能作为对照，不能代替本项目的自动化或目标平台验证。
